> Built during my Summer 2025 software engineering internship at **Kenmou Enterprise** in Taipei: an order-processing dashboard that gave the production floor one live view of every order — status, throughput, and what to act on next. The code is proprietary, so there's no public repo; this page is the spec.

## The problem

Kenmou is a packaging manufacturer. Before the dashboard, an order's journey lived in email threads, paper forms, and a few people's heads. Production staff couldn't see where an order stood without asking someone, packaging-prototype approvals waited on email chains, and throughput was something you felt rather than measured.

## What I built

- **An order-processing dashboard** — React on the front, Node on the back, SQL as the system of record — that the production floor ran on daily. Orders, statuses, and workflow stages in one view, built for people standing at a workstation, not engineers at a desk.
- **ArtiosCAD integration** — packaging prototype designs were wired into the internal approval workflow, so a prototype moved from CAD to sign-off without leaving the system.
- **The team's first Docker-based CI/CD pipeline** — before it, a release was a manual afternoon; after it, a push. This outlived my internship by design.
- **A digital inspection checklist** that replaced paper sheets. Measurable: −12% paper usage. Immeasurable: −100% lost forms.

## The result

Order throughput went up **40%** against the pre-dashboard baseline — mostly because nobody had to chase information anymore. The tools were built for users who are not engineers, which is the constraint that shaped everything: fewer screens, clearer states, no configuration.

## Context

Built as a software engineering intern, May–September 2025, Taipei. The dashboard is internal production software owned by Kenmou Enterprise, so the source is not public — the [experience timeline](/#experience) and my resume carry the verifiable details.
